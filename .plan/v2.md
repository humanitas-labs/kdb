# kdb v2 — rewrite plan

Last updated: `2026.10.02`

Status: Built. All four domains merged into `v2` (24e37a3), 7.9k lines including tests, 70 tests pass. `check --orphans` diffs empty against v1 on the humanitas workspace. Remaining: build order step 5, parity in daily use and the swap.

## Why

v1 is 34k lines, most of it code-language support (tree-sitter extractors and import resolvers for Rust, TS, Python, Go, C#), full-text search, fmt headers, and codemaps. Daily use is the markdown link graph (`check`, the Zed LSP diagnostics) and the task layer (`projects`, `tasks`, `spaces`, `cycles`, `render`). Rewrite from scratch, target under 8k lines including tests.

## Decisions, settled

- **Keep SQLite, not Dolt.** Beads uses Dolt because its agents hold divergent copies across worktrees and machines and must merge. Here every agent on this machine writes the one file `.kdb/index.db`. WAL mode, a busy timeout of a few seconds, and seq assignment inside the insert transaction cover multi-writer `par()` agents. Revisit only if a second machine or divergent copies appear.
- **Keep the relational schema as the contract.** Tables: projects, spaces, tasks, task_labels, labels, cycles, task_statuses, project_statuses, meta. The live db has 49 projects, 5 spaces, 856 tasks. Drop the `search_*` and `collections` tables on first run (they are ~200 MB of the 203 MB file). Consider renaming `index.db` since it is no longer an index.
- **Markdown graph lives in memory, not SQLite.** Rebuilt from files on each run, as v1 `check` already did. The LSP holds it in memory.
- **Binary is `kdb2` until parity**, then rename to `kdb` and merge `v2` into master. The installed v1 `kdb` and the Zed extension keep working meanwhile.
- **Issues stay on master** in `projects/kdb/.issues/` (they were cleared from the branch). The two v2 issues are [iss-0070 status icons](../../kdb/.issues/iss-0070-status-icons.md) and [iss-0071 task dependencies](../../kdb/.issues/iss-0071-task-deps.md).
- **Product description** is [docs/landing-copy.md](../docs/landing-copy.md), the v1 landing text. It already describes exactly the v2 scope. Fix before reuse: alias is 2–6 chars, not 3. (`.cycles/` already removed; cycles are not rendered to files.)

## Scope

Keep:

- Workspace root via `.kdb/`, ignore rules
- Markdown index: headings as symbols, standard links and wikilinks as references, `![[]]` embeds
- `check` (broken links, broken embeds, orphans), `outline`, `refs`, `render <file>` (transclusion)
- LSP: diagnostics for broken links first; go-to-definition and completion for links; hover and document symbols optional
- `projects`, `spaces`, `tasks`, `cycles`, `labels`, `statuses` on the existing schema
- `render --project | --space` materializing `.tasks/index.md` and per-task files
- New: task dependencies and `tasks ready` (iss-0071); status icons in rendered tables (iss-0070, SVGs in `docs/assets/`)

Drop: all code languages, `resolve/`, `symbols/extract`, `deps/`, `fmt` and LSP formatting, `codemap`, `search`/`index`/`collection`, `graph`, `tree`, self-updater and install script, benchmarks, landing app.

Deps: anyhow, clap, chrono, ignore, rusqlite (bundled), serde, serde_json, tokio, tower-lsp, tree-sitter, tree-sitter-md. Already in `Cargo.toml`.

## Module tree and ownership

Two trunks share only `workspace.rs` and the clap skeleton. `main.rs`, `workspace.rs`, `db/` are the seed and are frozen; each domain owns its directory and its test file. Agents may add dependencies to `Cargo.toml` and touch nothing else outside their scope. Agents do not commit; the main session reviews and commits each branch, then merges in order graph, plan, render, lsp.

Dropped on top of the Scope list: prosaic `use`/`run` checking (zero hits in the workspace), hover and document symbols in the first LSP pass, `tasks import`.

## Build order

1. **Workspace + markdown graph.** Root discovery, file walk, heading and link extraction, resolution. `check` and `outline` on top. This is the daily-use path; parity with v1 `check` output on the humanitas workspace is the test.
2. **LSP.** Diagnostics from the same graph, then definition and completion. Point Zed at `kdb2 lsp` beside the v1 server to compare.
3. **Task layer.** Open the existing db, drop search tables, WAL + busy timeout. Port `projects`, `spaces`, `tasks`, `cycles`, `labels`, `statuses`. Add `task_deps`, `tasks ready`, `tasks deps`, and the `parked` is_closed fix per iss-0071.
4. **Render.** `render --project/--space` with the icon column (iss-0070) and the Blocked-by column (iss-0071). `render <file>` for transclusion.
5. **Parity and swap.** Rename binary to `kdb`, `cargo install`, update the Zed extension, merge to master, remove the worktree.

The v1 test suites (`tests/lsp.rs`, `tests/cli.rs`, `tests/render.rs` on master, commit 96bd353) are a parity spec; port cases, not code.
